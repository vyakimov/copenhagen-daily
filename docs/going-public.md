# Going public: the checklist

Status: notes from 12 October 2026, to revisit before the paper is promoted (a friend's network, a
Reddit post). Written against the site as delivered that day, see [AWS delivery](aws-delivery.md).
The one item already done is the evidence trail no longer showing publishers' headlines (decision log,
12 October 2026). Nothing else below is built.

## 1. Licensing, the blocker that is not technical

The decision log has said since the start that publisher licensing is the largest unresolved risk and
deserves an answer before the site is promoted. Promotion is what this document is for, so this comes
first.

Where the paper stands:

- The copy is own-words summaries and every headline links to the primary source. The public
  `edition.json` carries no publisher body text, no local paths, no model names. There is no tracking
  and no revenue. This is about as defensible as an aggregator gets.
- Denmark implemented the EU press publishers' right in June 2021 as sections 52c and 69a of the
  copyright act. DPCMO (Danish Press Publications' Collective Management Organisation) administers it,
  says it represents 97 to 99 per cent of Danish publishers, and has taken the position that any
  service sharing publishers' content needs a licence; it has pursued LinkedIn and (via the Rights
  Alliance) Apple. Hyperlinks and "very short extracts" are carved out by the directive. DPCMO has also
  licensed an AI product (ProRata), so a non-commercial answer is not unthinkable.
- Original headlines were the one place a publisher's words appeared on the page. Removed on
  12 October 2026.
- Callout quotes are speech by public figures, lifted verbatim from one outlet's text with that outlet
  named. Defensible quotation; keep them short.

Still to do:

- [ ] Read the RSS terms of the four paywalled sources: Financial Times, Wall Street Journal, The
      Economist, The New York Times. Their feed terms typically restrict use to personal,
      non-commercial consumption. A personal digest sits inside that; a public site built from the
      feeds is a grey zone even without money. Decide per publisher: keep, or drop from the public
      edition (`ingest/config/sources.yaml` and `publisher/config/title.yaml`).
- [ ] Send DPCMO or a media lawyer a one-page description of the paper (what is reproduced, what is
      linked, no tracking, no revenue, machine-written) and ask whether a licence is needed.
- [ ] Only then post anywhere. Posting first is a bet that nobody from the sixteen newsrooms looks.

## 2. The technical flip from unlisted to public

Three noindex layers and one check that would start failing:

- [ ] The meta tag in `publisher/site/src/layouts/Broadsheet.astro`
      (`noindex, nofollow, noarchive, noimageindex`).
- [ ] The disallow-all `publisher/site/public/robots.txt`. Replace with an allow-all that names a
      sitemap.
- [ ] The CloudFront viewer-response function that adds `X-Robots-Tag: noindex, nofollow` to every
      object (distribution `E67FD57M9R899`).
- [ ] `editorial/src/news_editorial/verify.py` fails the morning check when the robots header is
      missing (`robots_header`, and the remedy text at the `problems.append` for it). Flip to the
      opposite assertion, or the 06:00 report says the site is broken every day.
- [ ] Head metadata for sharing: `<meta name="description">`, Open Graph title and description (and an
      image, the device PNG is a candidate), `<link rel="canonical">`. A Reddit post with no preview
      card does badly. The CSP (`img-src 'self'`) does not block any of this.
- [ ] A sitemap of editions, generated by the Astro build.

## 3. What a stranger needs that a household never did

- [ ] **An about page.** There is none. It should say the paper is machine-written from publishers'
      RSS feeds by a described process, who runs it, that nothing is tracked, and how to report an
      error. Disclosing the AI authorship up front is both honest and the best defence against a
      hostile thread. Link it from the folio.
- [ ] **A working corrections address.** The folio prints `newsroom@copenhagen-daily.net` from
      `publisher/config/title.yaml`. Confirm the mailbox actually receives mail; a publisher's first
      move is usually an email.
- [ ] **A 404 page.** A missing path currently returns S3's XML 403 (the bucket is private). One
      CloudFront custom error response mapping 403 and 404 to a static page fixes it.
- [ ] **A cache policy on HTML.** The front page is served with no `Cache-Control` header. CloudFront
      is invalidated on publish, but browsers apply heuristics from `Last-Modified`, so a returning
      reader at 06:05 can see yesterday's paper for hours. Give `index.html`, `latest.json` and
      `index.json` a short `max-age`; the immutable `n/<edition>/` and `a/<assets>/` trees can be long.
      Set it in the deliver step (`aws s3 sync` takes `--cache-control` per invocation, so two syncs
      or a CloudFront response-headers policy).
- [ ] **A feed.** Readers who like it will ask how to subscribe. An RSS or Atom feed of editions is a
      small Astro page and fits a paper built from RSS.

## 4. Operations for an audience that is not you

- [ ] **Staging first.** The roadmap's staging paper (second bucket and distribution at
      `staging.copenhagen-daily.net`, a `target` on the delivery config) exists to stop every change
      running for the first time in production at 05:30 with nobody watching. Build it before adding
      strangers, and do the noindex flip there first.
- [ ] **CloudFront free plan quotas.** Two viewer functions run on every request, so function
      invocations may run out before bandwidth does. Check the plan's monthly limits and what happens
      when they are exceeded; a good Reddit day is tens of thousands of requests.
- [ ] **External alerting.** The verify job's silence is the current failure signal, which only works
      if someone is watching. The roadmap's Cronitor idea (each launchd job pings on start and success)
      becomes necessary once failures are visible to others.
- [ ] **A stale notice.** If the 05:30 run fails the site silently shows yesterday. A reader-visible
      line when the edition is older than a day costs little and is the honest behaviour of a daily.
      It can be computed at build time only, so it has to be a date comparison in the page's own
      JavaScript, which the CSP currently forbids (`default-src 'none'`, no `script-src`), or a
      wording in the ear that already states the cutoff. Prefer the wording.
